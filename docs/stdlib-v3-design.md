# Stdlib V3 Design

Status: 0.9.0 implementation contract.

Stdlib v3 extends the 0.8 helper model without changing the import and
versioning contract. Helpers remain thin expansions over visible Minecraft
commands or JSON values, and value helpers must be passed to another helper or
JSON declaration rather than emitted as hidden commands.

## Added Modules

`from stdlib import storage, item_component, selector, position` activates the
new value helper modules. `import stdlib` activates them with the rest of the
stdlib for compatibility.

| Module | Helpers | Generated value |
| --- | --- | --- |
| `storage` | `storage.path(part, ...)` | `part...` joined with `.` |
| `storage` | `storage.child(path, child)` | `<path>.<child>` |
| `storage` | `storage.index(path, index)` | `<path>[<index>]` |
| `item_component` | `item_component.components(component, ...)` | merged item component object |
| `item_component` | `item_component.custom_name(component)` | `{"minecraft:custom_name": <text component>}` |
| `item_component` | `item_component.lore([components...])` | `{"minecraft:lore": [<text component>, ...]}` |
| `item_component` | `item_component.unbreakable()` | `{"minecraft:unbreakable": {}}` |
| `selector` | `selector.current()` | `@s` |
| `selector` | `selector.nearest_player()` | `@p` |
| `selector` | `selector.all_players()` | `@a` |
| `selector` | `selector.all_entities()` | `@e` |
| `selector` | `selector.tagged(tag)` | `@e[tag=<tag>]` |
| `selector` | `selector.players_tagged(tag)` | `@a[tag=<tag>]` |
| `selector` | `selector.entity_type(id)` | `@e[type=<id>]` |
| `position` | `position.here()` | `~ ~ ~` |
| `position` | `position.absolute(x, y, z)` | `x y z` |
| `position` | `position.relative(x, y, z)` | `~x ~y ~z`, using bare `~` for zero |
| `position` | `position.local(x, y, z)` | `^x ^y ^z`, using bare `^` for zero |

Value helpers produce plain storage path strings, item component JSON objects,
selectors, or coordinate strings. A standalone call such as
`storage.path("state")`, `item_component.unbreakable()`,
`selector.nearest_player()`, or `position.here()` is an error because it would
not generate a visible command.

`storage.path()` components are deliberately narrow: each component must be a
single non-empty path component without `.`, `[`, or `]`. Use raw string paths
for advanced NBT path syntax that is not covered by the helper.

Example:

```python
from stdlib import storage

def save():
    storage.set(storage.path("players", "current"), "alex")
    storage.get(storage.index("players.events", 0))
```

generates:

```mcfunction
data modify storage mypack:global players.current set value "alex"
data get storage mypack:global players.events[0]
```

`item_component.*` helpers are JSON-only in 0.9. They are intended for
`datapack.item_modifier()` declarations using Minecraft's `set_components`
item modifier, not for raw `/give` or item-stack command syntax.

Example:

```python
from stdlib import datapack, item_component, text

datapack.item_modifier("items/reward_components", {
    "function": "minecraft:set_components",
    "components": item_component.components(
        item_component.custom_name(text.colored("Cobble Reward", "gold")),
        item_component.lore([
            text.plain("Generated by Cobble"),
            text.colored("Keep this item", "gray")
        ]),
        item_component.unbreakable()
    )
})
```

generates an item modifier JSON resource with:

```json
{
  "function": "minecraft:set_components",
  "components": {
    "minecraft:custom_name": {"text": "Cobble Reward", "color": "gold"},
    "minecraft:lore": [
      {"text": "Generated by Cobble"},
      {"text": "Keep this item", "color": "gray"}
    ],
    "minecraft:unbreakable": {}
  }
}
```

## Entity Additions

`entity.teleport(target, destination)` emits:

```mcfunction
tp <target> <destination>
```

Both arguments accept strings or value helpers. For example:

```python
from stdlib import entity, selector, position

def move_up():
    entity.teleport(selector.current(), position.relative(0, 1, 0))
```

generates:

```mcfunction
tp @s ~ ~1 ~
```

## Schedule Cancellation

The existing `schedule` module remains a visible command wrapper in 0.9:

```python
from stdlib import schedule

def refresh():
    schedule.once("tick", "20t", "replace")
    schedule.clear("tick")
```

generates:

```mcfunction
schedule function mypack:tick 20t replace
schedule clear mypack:tick
```

`schedule.clear()` is Cobble's explicit cancellation helper. Cobble does not
create hidden scheduled functions or recurring loops for these helpers.

## Diagnostics

- Missing module imports keep using `stdlib-module-not-imported`.
- Standalone storage path helpers report that the helper returns a storage path
  string.
- Standalone item component helpers report that the helper returns an item
  component JSON object.
- `item_component.components()` rejects duplicate component keys.
- Standalone selector helpers report that the helper returns a selector string.
- Standalone position helpers report that the helper returns a coordinate
  string.
- `schedule.once()` accepts `append` or `replace` when a mode is supplied, and
  `schedule.clear()` requires exactly one function id.
- Arity diagnostics name the exact helper, for example
  `position.relative() takes 3 arguments`.
