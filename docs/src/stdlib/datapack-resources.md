# Data Pack Resources

Top-level `datapack.*` declarations write Minecraft JSON resources:

```python
from stdlib import datapack

def setup():
    /say Ready

datapack.function_tag("minecraft:load", ["mypack:setup"])
datapack.item_tag("rewards", ["minecraft:diamond", "minecraft:emerald"])
datapack.predicate("lucky", {
    "type": "minecraft:random_chance",
    "chance": 0.25
})
```

Use a lowercase ID such as `checks/lucky` for the current namespace, or
`mypack:checks/lucky` for an explicit namespace. Names are string literals;
resource contents must be known at build time.

## Declarations

| Helper | Contents |
| --- | --- |
| `datapack.function_tag(name, values)` | Function IDs or function tags |
| `datapack.block_tag(name, values)` | Block IDs or tags |
| `datapack.item_tag(name, values)` | Item IDs or tags |
| `datapack.entity_type_tag(name, values)` | Entity type IDs or tags |
| `datapack.dialog_tag(name, values)` | Dialog IDs or tags |
| `datapack.predicate(name, json)` | Predicate object |
| `datapack.advancement(name, json)` | Advancement object |
| `datapack.loot_table(name, json)` | Loot table object |
| `datapack.recipe(name, json)` | Recipe object |
| `datapack.item_modifier(name, json)` | Modifier object or list |
| `datapack.dialog(name, json)` | Dialog object |

## Tags

Repeated declarations merge and deduplicate their values. Function tags keep
source order; load and tick listeners join that same order, after Cobble's
load setup. An optional third boolean argument sets `replace`.

Optional entries use `required: False`:

```python
from stdlib import datapack

datapack.item_tag("rewards", [
    "minecraft:diamond",
    {"id": "other:bonus", "required": False}
])
```

Write namespaced function IDs, such as `mypack:setup`. An ID without a
namespace inside a function tag means `minecraft:`.

## JSON Resources

Use Minecraft 26.3 formats. Cobble checks resource shapes, required fields,
known vanilla IDs, and references in `minecraft` and the pack's namespace.
Other namespaces may be supplied by mods or other packs.

Common changes from older Minecraft formats:

| Resource | Current form |
| --- | --- |
| Predicate | `type` instead of `condition` |
| Item modifier | `type` instead of `function`; one `condition` instead of a `conditions` list |
| Loot table | `modifier` instead of `functions`; one `condition` instead of `conditions` |
| Recipe ingredient | An item ID, `#tag`, or list of item IDs |
| Item stack | `id` instead of `item` in an object |

Resource JSON accepts literals, constants, and component helpers. Runtime
variables and parameters cannot appear in a resource file. Conflicting
JSON declarations for the same ID are errors.

A list passed to `datapack.item_modifier` becomes a `minecraft:sequence`
that applies its entries in order.

## Item Components

`text.*` and `item_component.*` build JSON without emitting commands:

```python
from stdlib import datapack, item_component, text

datapack.item_modifier("reward", {
    "type": "minecraft:set_components",
    "components": item_component.components(
        item_component.custom_name(text.colored("Reward", "gold")),
        item_component.lore([text.plain("Generated by Cobble")]),
        item_component.unbreakable()
    )
})
```

## Checking The Output

```bash
cobble check
cobble build --validate --zip
cobble inspect output --json
```

Resources are included in ZIP output and listed by `cobble inspect`.
